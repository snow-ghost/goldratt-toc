# Проверка ограничения по данным

Это прикладной протокол диагностики для скилла. Он развивает шаг identify;
формулы и критерии ниже не являются дословным протоколом Голдратта.

## Минимальные данные

Собери доступное; не превращай список в обязательную анкету.

| Данные | Для чего нужны |
|---|---|
| Границы, единица результата, период, спрос | Не спутать локальный выпуск с целью системы |
| Маршруты и классы заказов, доли каждого класса | Сравнить реальную нагрузку этапов |
| Доступное время ресурса и причины его потерь | Оценить эффективную мощность |
| Время обработки и переналадок, качество, возвраты | Учесть работу, которая не даёт нового результата |
| Очередь и её возраст по этапам во времени | Отличить устойчивое накопление от разового всплеска |
| Время начала и завершения, ожидания и блокировки | Найти механизм потерь потока |
| Общие специалисты, оборудование, окна согласований | Не посчитать одну мощность несколько раз |
| Завершённый результат и исполнение сроков | Проверить эффект на выходе |

Проверь полноту временных меток, одинаковые определения «готово», рабочие
календари и единицы. Разделяй время обработки и полное время прохождения.
Пропущенные данные не равны нулю; среднее по несопоставимым заказам может скрыть
ограничение отдельного класса.

## Расчёт нагрузки

Для ресурса r за выбранный период:

`нагрузка_r = Σ(число заказов класса k × ожидаемое время ресурса r на заказ k)
              + время переналадок, не включённое в время на заказ`.

Время на заказ должно учитывать повторные посещения и переделки. Сравни
нагрузку с фактически доступным временем; не считай перерывы и потери дважды.
Отношение нагрузки к доступному времени выше 1 означает нехватку мощности
для этого состава спроса. Это кандидат в ограничение, а не доказательство
его единственности или первопричины.

Для простого последовательного потока одинаковых изделий, где каждый заказ
проходит каждый этап, оценка потолка:

`выпуск ≤ min(готовый спрос, эффективные мощности этапов)`.

Все величины здесь — годные единицы за один период. Для ветвлений, сборки,
разных маршрутов и общих ресурсов сначала переведи работу в нагрузку ресурсов;
минимум несопоставимых количеств задач использовать нельзя. При существенной
вариативности средние мощности дают лишь грубый ориентир.

## Признаки и альтернативы

| Наблюдение | Возможный механизм | Что проверить |
|---|---|---|
| Перед этапом растёт очередь готовой работы | Недостаточная эффективная мощность | Возраст очереди, состав спроса, потери времени, правила запуска |
| Этап часто ждёт входов | Поставки или несогласованная подготовка | Готовность комплекта, доступность входов, план выпуска |
| Этап не может передать готовую работу | Блокировка ниже по потоку | Приёмка, место хранения, лимиты, релизные окна |
| Высокая занятость при слабом результате | Переделки, переключения, локальные KPI | Доля годной нужной работы, возвраты, причины приоритетов |
| Производство свободно, готовое не продаётся | Недостаток исполнимого спроса или неверный ассортимент | Заказы, конверсия, причины отказов, пригодность предложения |
| Очередь перемещается между командами | Общий ресурс, вариативность или правила | Временной ряд, расписание ресурса, изменения состава работ |

Не объясняй поведение людей ленью по одному показателю загрузки. Не называй
корневой причиной метку «менеджмент»: найди наблюдаемое решение или правило.

## Проверка гипотезы

Спроси: если добавить полезный час именно здесь, какая завершённая работа
появится на выходе и когда? Назови зависимости, которые могут поглотить эффект.
Подходящий пилот защищает время ресурса, готовит входы, снимает конкретное
согласование либо на короткий период добавляет мощность. Меняй один механизм
или явно учитывай несколько изменений.

Пример с синтетическими данными: спрос — 100 годных единиц/день, мощности
A/B/C — 120/70/90. Кандидат — B; его увеличение до 85 позволяет ожидать
потолок 85, до 110 — только 90 из-за C. При спросе 60 увеличение B само по себе
не увеличит продажи. Предположения: одинаковый маршрут, согласованные единицы,
нет скрытых общих ресурсов и дополнительных потерь.

Сильный диагноз опирается на согласующиеся данные потока и проверку вмешательством.
Рассказ участников и расчёт средних дают предварительную гипотезу. Даже успешное
сравнение «до/после» может смешивать эффект с изменением спроса и состава работ;
отрази это в уверенности вывода.
